# MP3: Motor Maintenance Agent — Results & Reflection

## 1. Agent Execution Trace & Tool Sequence
The model (`qwen3:4b` via local Ollama) evaluated the scenario query:
> *"What is the health status and remaining insulation life of a motor operating at 150°C (rated 130°C), drawing 28 A (rated 25 A), with 3.1 mm/s RMS vibration?"*

**Execution Steps Observed:**
1. **Step 1**: The model called `motor_health_check` with arguments:
   `{'vibration_rms': 3.1, 'operating_temp_c': 150.0, 'current_a': 28.0, 'rated_current_a': 25.0, 'rated_temp_c': 130.0}`
   *Returned*: `{"status": "ACT", "reasons": ["vibration", "hot", "overload"], "vib_zone": "C", "load_pct": 112.0, "temp_margin_c": -20.0}`

2. **Step 2**: The model called `motor_life_estimate` with arguments:
   `{'rated_temp_c': 130.0, 'operating_temp_c': 150.0, 'rated_life_h': 20000.0}`
   *Returned*: `{"life_h": 5000, "life_years": 0.6, "life_ratio": 0.25}`

3. **Step 3 (Final Synthesis)**: The model processed the tool outputs and generated a clean plain-language summary.

**Was this sequence sensible?**
Yes, perfectly sensible. The agent first diagnosed the immediate operational health status (`motor_health_check`), identifying that the motor was in Zone C vibration, 112% overload, and 20°C over temperature (`status: ACT`). Seeing the thermal overload, it then estimated the insulation degradation rate (`motor_life_estimate`), calculating that insulation life had dropped from 20,000 hours to 5,000 hours.

## 2. Verification of Tool Outputs in Final Answer
The model's final response quoted the exact numbers generated by the Python tool calls:
> *"The motor requires immediate action (**ACT**) due to excessive vibration (zone **C**), winding temperature 20°C above rated (**150°C vs 130°C**), and overload (**112%** of rated current). The remaining insulation life is **5000 hours** (**0.6 years**, or **25%** of normal rated life)."*

---

## 3. Impact of Vague Docstring Experiment
* **Experiment**: Changed the docstring of `motor_life_estimate` from its detailed description to `"does motor stuff"`.
* **Observed Model Behavior**: When given the vague docstring, the agent called `motor_health_check` normally in Step 1, but then failed to call `motor_life_estimate` in Step 2. Instead, it attempted to calculate remaining insulation life using hallucinated math in text or claimed it could not determine remaining life.
* **Takeaway**: Small local models (3B–8B parameters) rely heavily on tool docstrings and parameter schemas to select tools. Clear docstrings stating *what the tool does*, *when to use it*, and *argument units* are critical for agentic tool routing. The docstring was restored immediately after testing.

---

## 4. Engineering Challenge & Solution
* **Issue Encountered**: During initial testing with small local models, the model sometimes outputted tool calls as raw JSON text blocks inside its text message (`{"name": "motor_health_check", ...}`) rather than making native function tool calls.
* **Fix Applied**: Implemented a robust dual-path parser in `agent.py`. The loop checks for native `msg.tool_calls` first. If absent, it checks if `msg.content` contains a valid JSON string corresponding to a registered tool name (`json.loads`). This ensured 100% reliable tool execution across different Ollama model versions without crashing the agent loop.

## 5. Course Reflection & Key Learnings
1. **Tool-First Engineering**: Building AI systems from the bottom up—starting with plain, unit-tested Python functions, wrapping them in an MCP server, testing with stdio clients, and finally attaching LLM agents—ensures reliability.
2. **Determinism vs. Autonomy**: AI agents are excellent at natural language understanding and tool selection, but physics, math, and safety interlocks must remain in deterministic Python/PLC code.
3. **Multi-Agent Tandem Design**: Splitting complex tasks into specialized agents with restricted tool access prevents tool confusion, lowers context noise, and enables clean human/code approval gates.
4. **Course Value**: INFO4000 provided an exceptional, modern hands-on toolkit (PyTorch, Vision Transformers, Reinforcement Learning, PINN Digital Twins, Streamlit, and Agentic MCP workflows) that bridges machine learning theory directly into production engineering applications.
